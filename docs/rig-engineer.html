Windows · Automobilista 2

Rig Engineer

Checks Steam, MOZA device status and saved controls between drives. At your next visit, a guided cockpit check can trace steering and pedal movement from the Windows controller to AMS2.

What it checks

Idle Windows desktop
Reads Steam’s local AMS2 manifest for pending work, Windows Plug and Play for configured MOZA devices, and a fingerprint of the saved AMS2 controller profile. A powered-off base can be expected. A reported device fault or profile change can raise a silent Windows notification.
AMS2 running
Defers idle work. The scheduled run can take a silent ten-second sample of AMS2 shared memory. This shows channels that changed on the viewed car. Player identity and physical inputs remain unconfirmed, and an unused channel can remain unknown.
Driver-confirmed parked check
In your own live cockpit, parked in neutral with AI driving off, you respond to one cue each for steering, throttle and brake. The check can correlate each gesture with a selected Windows controller axis and the corresponding AMS2 response. It can flag a missing or unexpected simulator response. Calibration and force feedback require separate checks.

How evidence reaches the Race Chief

The current-user Windows task runs at logon and every 15 minutes while the machine is awake. It launches the same Node CLI used at the rig. The checks and reports run locally without model inference.

What to do at the rig

Read the timestamps

From the Rig Engineer package, read status using the same private state directory as the scheduled task. If the task specifies a directory, pass it with --data-dir.

node preflight.mjs status --json

The last attempt can be deferred while the last completed observation remains available. Also check when the driver last confirmed inputs. A completed run can contain a blocker or an unknown.

Verify the bindings

Park clear of traffic in a practice or test session, select your own live cockpit and use stationary neutral with AI driving off.

node preflight.mjs check-inputs --parked-driver

Return focus to the cockpit. After five seconds of qualifying telemetry, turn the wheel on one beep, apply throttle on two, and brake on three. Move one control at a time, hold briefly, then release or center it.

Enroll a recovery copy

Add --enable-repair to the guided command to enroll verified bindings after an initial preflight. If you verified the bindings yourself, use accept-controls --fingerprint HASH --enable-repair with the exact hash from status. Acceptance alone records the comparison baseline.

Verify a restore

A later idle cycle can restore only an enrolled, missing profile. It verifies the stored bytes and destination, creates the file only if the path is still absent, then checks the bytes on disk. An existing changed profile stays flagged for review. Use disable-repair to turn off future restores.

Use a fresh cockpit check to verify how restored bindings behave. Check hardware behind the base in Pit House or the simulator. For shared-memory setup and recording checks, see the live simulator validation guide.
